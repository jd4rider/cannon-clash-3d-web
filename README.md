# Cannon Clash 3D

A Unity WebGL build served from GitHub Pages as part of
[Little Joy Arcade](https://littlejoyarcade.site).

- **Play:** <https://jd4rider.github.io/cannon-clash-3d-web/play/>
- **Cover page:** <https://jd4rider.github.io/cannon-clash-3d-web/>

## What is in here

```text
build/WebGL/                the untouched Unity WebGL export (81 MB)
scripts/prepare-site.mjs    turns that export into a Pages-servable site
site/                       generated by the script, not committed
.github/workflows/pages.yml prepare + deploy on every push to main
arcade-manifest.json        the catalogue entry for littlejoyarcade.site
```

There is no bundler, no framework and no dependencies. The only build step is
`prepare-site.mjs`, which needs nothing but Node.

## Why there is a build step at all

Two things in the stock Unity template do not survive contact with GitHub Pages.

**Compression.** Unity's default export Brotli-compresses the payload
(`*.data.br`, `*.wasm.br`, `*.framework.js.br`) and expects the server to answer
with `Content-Encoding: br`. Pages serves files verbatim and lets you set no
response headers, so the browser would hand raw Brotli bytes to the loader and
the game would stop at the progress bar. This export already ships uncompressed
files; the script expands any `.br` payload it finds and points `index.html` at
the plain names, so a future compressed export still deploys.

**Layout.** The template pins the desktop player to a fixed 960 × 600 window and
lets phones stretch the canvas across the whole viewport. This is a landscape
game, so on a portrait phone that stretches it out of shape. The script replaces
the user-agent branch with a single fit-to-screen rule that keeps the canvas
aspect ratio and letterboxes it, centres the play area, and sets the page
background to the game's own colour so the bars are not white.

It also fails the build if a required file is missing, if the wasm module is not
the module Pages will be serving, or if `index.html` still references a
compressed payload.

## Local development

```bash
node scripts/prepare-site.mjs
python3 -m http.server 8080 --directory site
# open http://localhost:8080/play/
```

Serve it over HTTP rather than opening the file — Unity's loader fetches the
payload and will not work from a `file://` URL.

## Updating the build

Re-export from Unity, then replace `build/WebGL/` with the new export and push:

```bash
rm -rf build/WebGL
cp -R "/path/to/Cannon Clash 3D/Builds/WebGL" build/WebGL
git add -A && git commit -m "Update the WebGL build" && git push
```

Keep the export's compression setting on Brotli or Disabled; both work. Gzip and
`.unityweb` payloads are not handled by the script and fail the build with a
clear message.

## Platform integration

The build talks to the Little Joy Arcade SDK from C# and falls back to local
storage when the page exposes nothing (`[LittleJoy] Running on local fallback`),
which is what happens here: the player writes `cannonclash_save.json` through
Unity's own file system, so progress, stars and unlocks persist per browser
without the drop-in `arcade-client.js`. There is no compiled `.jslib` bridge in
the export, so sign-in and cloud saves are not wired up.
